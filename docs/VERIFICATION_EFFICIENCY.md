## 当前执行原则

- 先核对范围与实际差异，按最小必要文档定位问题；有明确文件和失败信息时不重新扫描整个项目。来源探索达到无法改变实现判断的程度就报告「未取得」，不重复翻来源脚本。
- 局部行为先用正式入口的定向调试，按文件或用例名定位；禁止猜分片编号。界面覆盖所有适用页面和视口，同一个失败模式不重复写多层断言。
- 安装、编辑和构建结束后运行一次 `auto`，让入口处理域并集、去重、并发和有效记录。测试失败只修对应问题，然后按差异补测；不另写逐域循环，不因一次局部失败重复所有已通过域。
- 测试期间不改冻结的源码、依赖和文档。测试、构建与媒体任务直接使用项目入口，不自行恢复机器级资源限额；取消只清理本任务，不影响他人工作。
- 一个运行会话对应一个结果。用支持的等待工具取得退出状态；不用反复读取同一日志尾部确认没有变化。共享锁交给入口等待，不同时另起同状态验证。
- 集成成功退出且主线提交核对后，按项目约定重启并核验运行态。验收聚焦实际变化，测试设施修改不重复应用交互的手工取证。
- 有协调授权仍须有实际依赖和处理者。已结束对话不承担状态接收或确认职责；当前任务能自主完成的集成、验证和收尾直接执行，持久交付由 Git 与项目证据承载。

## 衡量优化

用户于 2026-10-13 明确要求移除 CPU、内存、进程数、启动余量、线程限额和机器级重任务槽位。项目直接运行原生测试入口，保留按需选测、测试覆盖、代码快照证明与 Git 集成互斥。资源限额与代码一致性锁不是同一类约束，不把移除资源限额解释为跳过验收。

资源问题的证据：受限验证出现 `WinError 1816` 和 Git 启动失败；中止前采样最多 18 个进程（含入口父进程），私有提交内存峰值 1.410 GiB、单进程 1.110 GiB。该采样只覆盖中止前阶段，不能代表整套回归的峰值，也不能归因于内存不足。

原生并行浏览器验证中，紧凑密度即时样式与关注标题过渡期 DOM 各出现一次失败；相同文件分别运行均通过。相关时序测量文件进入串行批，保留全部行为断言，其余文件继续并行。不能把定向通过直接当作全量通过，也不以扩大超时或删断言处理取样竞争。

定向入口实测：`jav-detail.test.ts` 的 8 个浏览器用例全部通过，入口墙钟耗时 26.491 秒，其中浏览器 TAP 为 14.525 秒，Python 夹具与运行为 25.399 秒。这个数只说明相关文件可以快速复现，不能替代约 18 分钟的整域验收。记录复用回归确认三域基线发生前端差异时只调用 web，catalog 与 metadata 保留原验证时间；环境不一致、过期、共享变化与失败域仍需实际验证。

分别记录定向调试、正式验证、失败重跑、锁等待与集成耗时。纯工具写文件时间不能代表修改工时；并行测试用墙钟时间，不相加分片耗时。局部通过不代表完整验收通过；静态门槛只证明结构成立，不证明后续智能体已减少读取或消息。性能收益需要对应实际调用或行为回归，不把计划中的收益写成已取得。
